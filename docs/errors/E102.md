# E102 — config breaks a semantic rule

The file parsed cleanly, but cross-field validation rejected a
combination. Examples that surface as `E102`:

* `kernel.kind` not present in `packages`.
* `swap.kind=partition` without a `swap` partition role in the layout.
* `partitioning.lvm` without `encryption.kind=luks2`.
* `firmware=container` combined with disk-side fields (encryption,
  partitioning.custom, …).
* `encryption.header_path` set without a `luksheader` carrier in the
  layout.

The error message states which rule fired. Fix the offending field
and rerun `getarch validate <path>` to confirm.
